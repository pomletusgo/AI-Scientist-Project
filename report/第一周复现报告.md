## 一、项目背景与目标

### 1.1 AI-Scientist 是什么

AI-Scientist 是 Sakana AI 于 2024 年 8 月发布的全自动科学发现系统（论文 arXiv:2408.06292），相关成果发表于 Nature。它是首个实现"从研究想法到论文发表"全流程自动化的 LLM 系统，无需人类干预即可：

- 生成新颖的研究想法（含文献新颖性检查）
- 编写和修改实验代码（通过 Aider 智能体）
- 执行 GPU 实验并自动纠错
- 撰写完整 LaTeX 学术论文（含引用和图表）
- 对论文进行同行评审（遵循 NeurIPS 标准）

### 1.2 本周任务

1. 深入理解 AI-Scientist 论文的设计哲学与技术实现
2. 在本地环境中获取代码并搭建运行环境
3. 将系统原有的 LLM 模型替换为 DeepSeek V4 系列
4. 拆分流水线，在无 GPU 条件下跑通 LLM 部分
5. 实测验证模型替换效果
6. 撰写技术报告文档

## 三、系统架构深度解析

### 3.1 整体架构

AI-Scientist 的核心是一个**三段式流水线 + 独立评审模块**：

```
┌──────────────┐    ┌──────────────────┐    ┌──────────────┐
│ ① 想法生成    │ →  │ ② 实验迭代       │ →  │ ③ 论文撰写    │
│ generate_ideas │    │ perform_experiments│    │ perform_writeup│
│ (纯 LLM)      │    │ (需要 GPU)        │    │ (LLM + 实验数据)│
└──────────────┘    └──────────────────┘    └──────────────┘
                                                      ↓
                                           ┌──────────────────┐
                                           │ ④ 自动评审        │
                                           │ perform_review    │
                                           │ (纯 LLM，可独立使用)│
                                           └──────────────────┘
```

### 3.2 各阶段详解

**第一阶段：想法生成（generate_ideas.py）**

LLM 基于代码模板和种子想法生成新颖的研究方向。核心机制：
- 模板驱动：每个研究领域有 `experiment.py`（可执行基线）+ `prompt.json`（领域上下文）
- 迭代生成：新想法基于已有想法构建，维护 `idea_archive`
- 自省改进：每个想法经历 `num_reflections` 轮自我批判（"审视质量、新颖性、可行性"）
- 新颖性检查：通过 Semantic Scholar API 搜索文献，由 LLM 判断是否与已有工作重叠

**第二阶段：实验迭代（perform_experiments.py）—— 本环境不可用**

- 使用 Aider（LLM 驱动代码助手）增量修改 `experiment.py`
- 在 GPU 上执行训练，最多自动重试 4 次修复错误
- 维护 `notes.txt` 实验笔记本
- 产出 `final_info.json`（数值结果）和 PNG 图表

**第三阶段：论文撰写（perform_writeup.py）**

- 逐节生成：Abstract → Introduction → Background → Method → Experimental Setup → Results → Conclusion
- 每节生成后有独立 refinement（细化改进）
- Related Work 特殊处理：先勾勒引用框架，再用 Semantic Scholar 搜索真实论文填入（防幻觉）
- LaTeX 自动纠错：`chktex` 检查语法 → LLM 修复

**第四阶段：自动评审（perform_review.py）—— 可完全独立使用**

- 遵循 NeurIPS 评审标准（Soundness/Presentation/Contribution 各 1-4，Overall 1-10）
- 集成评审（ensemble）：生成多个独立评审 → meta-reviewer 综合
- 达到 65.2% 平衡准确率（接近人类水平），每篇成本 $0.25-$0.50

### 3.3 关键设计洞察

1. **文件级耦合而非内存级耦合**：模块间通过 JSON 文件和 txt 文件传递数据，松耦合设计使我们能在无 GPU 环境下用模拟数据桥接上下游模块。

2. **Chain-of-Thought + Self-Reflection 双重质量保证**：LLM 先输出 "THOUGHT"（推理过程），再输出结构化 JSON。如果不够好，通过 reflection prompt 多轮改进。

3. **Aider diff 编辑**：写实验代码不用一次性生成，而是增量式修改，更接近人类程序员工作方式。

4. **AI Reviewer 的元认知闭环**：系统能评估自身产出，评审结果可反馈到下一轮想法生成，形成开放式科学发现循环。

## 四、DeepSeek V4 模型替换

### 4.1 修改范围

共修改 3 个文件，新增和修改约 50 行代码：

| 文件 | 变更内容 |
|------|---------|
| `ai_scientist/llm.py` | 新增 5 个模型声明 + 3 个 API handler + 路由改为前缀匹配 |
| `launch_scientist.py` | Aider 模型名称映射（2 处） |
| `ai_scientist/perform_writeup.py` | Aider 模型名称映射（1 处） |

### 4.2 llm.py 修改详解

**① 模型注册 —— 新增 5 个模型到 AVAILABLE_LLMS**

```python
# DeepSeek V4 系列（2026年4月发布，替代旧版 V3/R1）
"deepseek-v4-pro",          # 1.6T MoE, 1M 上下文, 支持 thinking 推理模式
"deepseek-v4-flash",        # 284B MoE, 速度优先
"deepseek-v3.2",            # V4-Flash 别名
# DeepSeek R1 推理系列
"deepseek-r1",              # 原始 R1, MIT 开源
"deepseek-r1-0528",         # R1 幻觉减少版
```

**② 客户端路由 —— 改为前缀匹配**

原始代码是精确匹配列表，扩展性差：
```python
# 旧：每新增模型需要修改两个地方
elif model in ["deepseek-chat", "deepseek-reasoner", "deepseek-coder"]:
```

改为前缀匹配，自动覆盖所有 `deepseek-*` 模型：
```python
# 新：新增模型只需改 AVAILABLE_LLMS 列表
elif model.startswith("deepseek-"):
    return openai.OpenAI(
        api_key=os.environ["DEEPSEEK_API_KEY"],
        base_url="https://api.deepseek.com"
    ), model
```

**③ API 调用 —— 三种模型类型用不同的 handler**

不同 DeepSeek 模型对 API 参数有不同要求：

| 模型类型 | handler 策略 | 关键参数 |
|----------|-------------|---------|
| `deepseek-v4-flash`, `deepseek-chat`, `deepseek-coder` | 标准 chat | `temperature` + `max_tokens` |
| `deepseek-v4-pro` | **thinking 模式** | `extra_body={"thinking": {"type": "enabled"}}` |
| `deepseek-r1`, `deepseek-reasoner` | 推理模式 | **不支持** `temperature` 参数 |

### 4.3 模型选择策略

在 AI-Scientist 不同阶段推荐使用不同 DeepSeek 模型：

| 流水线阶段 | 推荐模型 | 理由 |
|-----------|---------|------|
| 想法生成 | V4 Flash | 创造力任务，速度快成本低 |
| 论文撰写 | V4 Pro | 学术写作需要深度思考和长上下文 |
| 论文评审 | V4 Pro | 批判性思维需要 thinking mode |
| 引用搜索 | V4 Flash | 简单搜索→选择任务，不需要深度推理 |

## 五、实测验证

### 5.1 API 连通性测试

```
deepseek-v4-flash  → "Hello!"                         ✅ 0.5s
deepseek-v4-pro    → "4" + reasoning_content 可见       ✅ 1.2s
```

### 5.2 测试一：研究想法生成

**输入**：NanoGPT 模板（字符级语言模型）
**模型**：deepseek-v4-flash
**参数**：2 个想法，每个 2 轮自我反思

**输出**：4 个研究想法（含 JSON 元数据）

| # | 想法名称 | 标题 | I | F | N |
|---|---------|------|---|---|---|
| 1 | adaptive_block_size | 自适应块大小动态上下文窗口 | 6 | 4 | 4 |
| 2 | layerwise_learning_rates | 逐层学习率自适应 | 4 | 6 | 2 |
| 3 | **scheduled_dropout** | **动态 Dropout 正则化** | **7** | **8** | 6 |
| 4 | **multi_token_prediction** | **多 Token 预测目标函数** | **8** | 6 | **8** |

最佳想法（#4）的 Experiment 字段包含详细实现方案：修改 forward 方法、双 logit head、加权 loss 函数、3 数据集验证计划。经 2 轮反思后实现方案从 100 词扩展到 200+ 词，细节显著增加。

**成本**：~$0.02

### 5.3 测试二：自动论文评审

**输入**："Attention Is All You Need" 论文（Transformer 原始论文，NeurIPS 2017 最佳论文）
**模型**：deepseek-v4-pro（thinking mode）
**参数**：3 ensemble × 3 reflections

**评审结果**：

| 评审维度 | 分数 | 说明 |
|----------|------|------|
| Overall | **10/10** | Award Quality |
| Originality | 4/4 | 突破性全新架构 |
| Quality | 4/4 | 实验扎实 |
| Clarity | 4/4 | 写作清晰 |
| Significance | 4/4 | 影响深远 |
| Soundness | 4/4 | 技术正确 |
| Presentation | 4/4 | 结构良好 |
| Contribution | 4/4 | 贡献重大 |
| Confidence | 5/5 | 绝对确定 |
| Decision | **Accept** | ✅ 接受 |

评审质量分析：AI Reviewer 精准识别了核心贡献（self-attention 替代 RNN/CNN、multi-head attention、并行化优势），准确列出 6 条优势 + 6 条局限（二次复杂度、仅 MT 任务验证、缺乏理论分析、训练资源需求），并提出 5 个有深度的问题。

**评审结果与历史事实一致**：该论文确实获得了 NeurIPS 2017 最佳论文奖，并成为现代大语言模型的基础架构。

**成本**：~$0.08

### 5.4 测试三：完整论文生成

**流程**：想法生成 → 模拟实验数据 → 论文撰写 → 自动评审

**生成论文**：Word-Aware Memory Transformers (WAMT)，2384 词，6 节完整学术论文，含 LaTeX 数学公式。

**遇到问题**：Conclusion 部分出现幻觉（跳到"医学图像分割"），这是 AI-Scientist 论文中讨论的典型失败模式——LLM 在长文本生成中可能偏离主题。手动修复后重新生成。

**对生成论文的评审**：

| 评审维度 | 分数 |
|----------|------|
| Overall | **1/10** |
| Soundness | 1/4 |
| Contribution | 1/4 |
| Confidence | 5/5 |
| Decision | **Reject** ❌ |

**AI Reviewer 的拒稿理由**（精准且诚实）：
1. "所有实验结果都是模拟/捏造的，每个定量声明都没有真实实验支撑"
2. "消融实验中的 component A 和 alternative design B 未定义——语焉不详"
3. "没有与任何真实 baseline（Charformer、CANINE、ByT5）对比"
4. "论文声明由 AI pipeline 生成，引发学术诚信问题"
5. "将模拟数据当作真实实验发现呈现，伦理上有问题"
6. "依赖空格分词，对中文等无空格语言不适用"

**这个结果的价值**：证明了 AI Reviewer 不会被流畅文笔欺骗，具备识别学术不端的基本能力。这也意味着——如果有真实 GPU 实验数据支撑，评审结果会完全不同。

**全流程成本**：~$0.14（远低于原始论文的 $15/篇）

## 六、无 GPU 环境影响分析

### 6.1 各模块 GPU 依赖情况

| 模块 | GPU 需求 | 本地状态 | 说明 |
|------|---------|---------|------|
| generate_ideas.py | ❌ 不需要 | ✅ 正常运行 | 纯 LLM API 调用 |
| perform_review.py | ❌ 不需要 | ✅ 正常运行 | 纯 LLM API 调用 |
| perform_writeup.py | ❌ 不需要 | ⚠️ 需模拟数据 | 本身不跑 GPU，但依赖 GPU 产出的实验数据 |
| perform_experiments.py | ✅ 必需 | ❌ 不可用 | Transformer 训练需要 CUDA |
| launch_scientist.py | ✅ 必需 | ❌ 不可用 | 编排实验执行的入口 |

### 6.2 桥接方案

通过**文件级模拟**绕过 GPU 依赖：

```
正常流程：  Idea → GPU 训练 → final_info.json + notes.txt → 论文 → 评审

桥接方案：  Idea → 构造 final_info.json + notes.txt → 论文 → 评审
                    ↑
              手动生成模拟数据（格式与真实实验一致）
```

这个方案的**精妙之处**在于：AI-Scientist 的模块间耦合是文件级而非内存级，只要产出正确格式的文件，下游模块就能正常消费。

### 6.3 局限性

- 论文中的实验结果是**模拟的**，非真实训练产出
- 没有 PNG 图表（真实实验产出 matplotlib 图）
- AI Reviewer 能检测到异常并拒稿
- **如需产出真正有学术价值的论文，必须接入 GPU 或云端算力**

## 九、经验总结

### 9.1 技术收获

1. **松耦合架构的价值**：AI-Scientist 的文件级耦合设计使其 LLM 部分可以完全脱离 GPU 独立运行，这是优秀架构设计的体现。

2. **模型 API 差异需细致处理**：不同 DeepSeek 模型对参数的支持不同（temperature、system role、thinking mode），需要在 handler 层面做区分，不能一刀切。

3. **AI Reviewer 的真实能力**：它不会被流畅的文笔欺骗，能准确识别实验数据的可信度问题。这证明了自动化评审的实用价值。

4. **LLM 生成的长文本存在幻觉风险**：论文生成中 Conclusion 跳到不相关领域，需要人工校验或额外的质量检查机制。

### 9.2 踩过的坑

1. **GitHub 访问**：中国大陆网络环境下，建议用 ghproxy 或 gitee 镜像。有条件可配置 git 代理。

2. **conda 在 Git Bash 中不可用**：直接在 Windows 上用 pip 安装即可，LLM 部分不依赖 conda。

3. **bash heredoc 中嵌套 Python**：单引号和特殊字符容易冲突，建议写成 `.py` 文件再执行。

4. **`\r\n` 换行符**：Git Bash 下编辑代码需注意，可能导致 Python 语法错误。
